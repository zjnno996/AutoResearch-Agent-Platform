## Method
The Auto Research workflow is organized as a staged pipeline. Early stages build the research context and collect evidence. Middle stages generate candidate ideas, produce an experiment plan, create executable code, and run sanity checks. Later stages execute the experiment, parse metrics, summarize findings, and produce writing artifacts. Each stage writes explicit files to the run directory so downstream stages can be audited.

For this smoke test, deterministic fallbacks are part of the method. When structured metrics, code execution status, or draft artifacts already exist locally, the pipeline can consume those files directly instead of requiring another long model call. This reduces fragility while preserving the rule that no unobserved experimental numbers should be introduced.
