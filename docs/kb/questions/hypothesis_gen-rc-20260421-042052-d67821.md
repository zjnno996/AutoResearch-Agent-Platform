# Stage 08: Hypothesis Gen

# Core Ideas

## Idea 1: Prefix-/early-representation-aware request scheduling
- One-sentence claim: 用请求前缀相似度或前2–4层轻量表示来分组与重排请求，可在混合在线负载下稳定优于纯 FIFO/长度分桶调度。
- Core novelty: 不是做重型跨层联合优化，而是定义一组低开销、稳定的“模型暴露信号”（prefix overlap、early embedding、KV footprint proxy）供调度器使用，并与传统调度可无缝回退。
- Why it matters: 该机制直接针对 continuous batching 和 KV 复用的真实瓶颈，若有效可在几乎不改模型的前提下同时改善吞吐和尾延迟。
- Minimal validation plan: 在单机多卡推理框架上比较 FIFO、长度分桶、prefix-aware、early-representation-aware 四种调度，在含共享 system prompt、长短混合、多轮对话的回放负载上测 TTFT、token throughput、P95/P99 latency 与调度开销。
- Key risk: 早期表示带来的额外提取与排序开销可能抵消收益，且其增益未必显著超过更简单的 prefix hash。

## Idea 2: Value-aware KV cache retention with selective recomputation
- One-sentence claim: 在线 LLM 服务中，按“未来复用价值”选择性保留 KV、其余摘要化或重算，比默认尽量保留全部 KV 更能降低显存峰值与尾延迟。
- Core novelty: 将 KV cache 从“默认资产”改为“需估值的负债”，基于复用概率、topic drift、retrieval 替换率等廉价信号做价值感知保留，并显式允许“重算优于迁移/保留”。
- Why it matters: 这直接命中长对话、RAG、工具调用场景中的显存碎片、跨卡迁移和 OOM 问题，有机会挑战当前“KV 越多越好”的默认设计。
- Minimal validation plan: 在长对话/RAG混合负载上比较 full retention、滑窗截断、随机/最近淘汰、value-aware retention(+ selective recompute)，测显存峰值、OOM/eviction 次数、P99 latency、吞吐和任务质量下降。
- Key risk: “价值”信号可能不够稳定，导致错误丢弃关键历史，重算成本也可能反过来拉低总体收益。

## Idea 3: Modular online serving beats deeper distributed coordination
- One-sentence claim: 对真实混合在线负载，prefill/decode 解耦 + 少卡副本池 + 条件触发 speculative decoding，可能比统一大池和更深多机协同取得更好的 SLO/成本表现。
- Core novelty: 不再默认“更强分布式协同=更优”，而是把 speculative、并行度和资源池设计都变成按负载条件触发的模块化策略，并用异常守护防止系统振荡。
- Why it matters: 该方向可回答一个关键系统问题：在线推理最优点到底在更深协同还是更强解耦；若结论成立，将显著影响实际服务架构选择。
- Minimal validation plan: 搭建两类对照系统——统一 worker 池/更深模型并行/默认 speculative vs prefill-decode 解耦/少卡副本池/选择性 speculative——在真实或回放混合负载下比较 P95/P99、SLO violation rate、吞吐和单位成本。
- Key risk: 对大模型或高利用率场景，模块化方案可能因资源碎片和副本冗余而输给更强的全局协同。

## Hypothesis 1: 低后悔的“前缀/早期表示感知调度”能优于纯长度/FIFO调度，但应坚持模块化接口而非深度联合控制

### Rationale
- 来自 innovator 的 strongest idea：**利用模型很早期的结构信号**（前缀、前几层表示）指导调度，而不是把调度完全视为模型无关。
- 来自 pragmatist 的 feasibility：先从**前缀相似度/哈希近似**做起，再扩展到前 2–4 层轻量表示；无需训练新模型。
- 来自 contrarian 的 critical concern：不要直接做“大一统跨层联合优化器”，而应采用**低后悔接口**：
  - 模型仅暴露稳定信号：prefix overlap、前几层 embedding、KV footprint proxy
  - 调度器只做简单分组/重排
  - 保留 FIFO/长度分桶作为 fallback

这使得假设保留新意，但避免“状态空间爆炸”和脆弱的黑箱联合优化。

### Measurable prediction
在混合在线负载（短问答、长 prompt、多轮对话、部分共享 system/retrieval prefix）上，相比 FIFO 与长度分桶：
- token throughput 提升 **≥ 10%**
- P95 latency 降低 **≥ 8%**
- TTFT 降低 **≥ 5%**
- 在低共享前缀负载上性能下降 **≤ 3%**

若使用“前几层表示”版本，则应比仅前缀哈希版本再多带来 **≥ 3%** 的吞吐或 tail-latency 改善，否则说明复杂化价值有限。

### Failure condition
拒绝该假设，如果出现任一情况：
- 相比长度分桶，吞吐提升 **< 5%** 且 P95 无显著改善
- 调度开销抵消收益
- 低共享前缀负载下退化 **> 3%**
- 早期层表示版并未显著优于简单前缀哈希版（说明“读模型内部状态”的复杂性不值得）

### Unresolved disagreement
- **Innovator** 认为早期层“结构轮廓”可能是关键新信号。
- **Contrarian** 认为简单 prefix-aware 调度可能已足够，进一步读模型内部状态未必值得。
- 因此此假设本身包含一个次级争议：  
  **“模型内部早期表示”是否真的比“廉价前缀相似度”更有系统价值？**

## Hypothesis 2: 在线 LLM 服务中，优化重点应从“尽量保留/复用全部 KV”转向“价值感知的 KV 保留与选择性重算”

### Rationale
- 这是 contrarian 最强、也最有研究辨识度的观点：**KV cache 不总是资产，很多时候是负债**。
- 它也吸收 innovator 的结构化思路：可以用廉价信号估计“哪些历史更值得保留”，例如：
  - prefix/shared context 复用概率
  - topic drift
  - retrieval 替换率
  - 历史块的重要性图
- pragmatist 角度上，该假设可先做**单机/小多卡原型**：
  - 完整保留 KV
  - 简单截断
  - 价值感知保留（保留高价值历史、低价值历史摘要化或丢弃并重算）

这比空泛地谈“更好 KV cache”更可证伪，也更贴近真实瓶颈：显存、碎片、尾延迟、迁移成本。

### Measurable prediction
在长对话、RAG、多工具调用混合负载中，相比“尽可能保留全部 KV”：
- 显存峰值下降 **≥ 20%**
- P99 latency 降低 **≥ 10%**
- OOM / eviction / stall 次数下降 **≥ 20%**
- 任务质量下降 **≤ 2%**（如 EM/F1、BERTScore、人工一致性抽检）

如果加入“必要时重算 prefill 而非迁移大 KV”的策略，则在高压负载下总体吞吐应提升 **≥ 8%**。

### Failure condition
拒绝该假设，如果：
- 完整保留 KV 在质量、吞吐、tail latency 上几乎全面更优
- 所谓“价值感知”信号无法稳定区分可丢弃历史与关键历史
- 重算与摘要化引入的额外成本抵消显存和调度收益
- 质量下降 **> 3%**

### Unresolved disagreement
- **Contrarian** 倾向认为“KV 被系统性高估”。
- **Pragmatist/Innovator** 更可能认为应先利用 KV，而不是激进遗忘。
- 真正未决的问题是：  
  **在什么负载区域，‘保留 KV’从资产转为负债？**  
  这需要通过负载分层实验回答，而不是先验假定。

## Hypothesis 3: 对真实混合在线负载，最优系统未必来自更深的分布式/联合优化；“阶段解耦 + 少卡副本池 + 条件触发优化”可能比复杂多机协同更稳

### Rationale
这是一个更高层、但非常关键的系统假设，综合了 pragmatist 和 contrarian 的核心：

- pragmatist 的强现实洞见：**prefill/decode 解耦**通常是最容易稳定获益的系统设计。
- contrarian 的核心挑战：**更复杂的分布式并行不一定更优**；在线 decode-heavy 服务往往更需要少同步边界、低 tail latency、强故障隔离。
- innovator 的贡献在这里转化为“条件触发优化”而非默认启用：
  - speculative decoding 不应默认全开，而应按任务/温度/acceptance 预估选择性启用
  - 异常检测可作为守护机制，防止解耦系统或偏置调度出现 oscillation

因此，这个假设不是“做更复杂的联合系统”，而是测试一个更大胆的命题：  
**在线推理里，模块化、少卡化、阶段隔离的组合，可能比深度分布式协同更优。**

### Measurable prediction
在真实或回放的混合负载上，对比两类系统：

1. **复杂方案**：统一 worker 池 / 更多模型内并行 / 全局默认 speculative  
2. **模块化方案**：prefill-decode 解耦 + 少卡副本池 + 仅对高收益任务启用 speculative + 异常守护

预测模块化方案可实现：
- 短请求 P95 latency 改善 **≥ 15%**
- P99 latency 改善 **≥ 10%**
- SLO violation rate 降低 **≥ 15%**
- 平均吞吐不低于复杂方案 **95%**，或在相同 SLO 下单位成本更优

若加入选择性 speculative，则相比“全量 speculative”：
- P99 更稳，波动降低 **≥ 10%**
- 平均吞吐损失 **≤ 5%**
- 资源利用率更可预测

### Failure condition
拒绝该假设，如果：
- 更复杂的多机并行/统一池方案在相同质量和成本下，同时显著优于模块化方案的平均吞吐与 tail latency
- prefill/decode 解耦收益 **< 5%**
- 选择性 speculative 明显不如全量 speculative
- 模块化方案因资源闲置导致总成本恶化太多

### Unresolved disagreement
- **Contrarian** 认为“去分布式化/少卡化”常常更优。
- **Pragmatist** 更谨慎，认为这可能依赖模型规模和负载结构，不一定普适。
- **Innovator** 可能仍相信更深入的跨层协同有长期价值。
- 因此核心未决分歧是：  
  **在线 LLM 服务的最优点，究竟在‘更深协同’还是‘更强解耦’？**  
  这不是概念争论，必须靠 workload × model scale × SLA 三维实验判断。

# 最终建议的研究顺序

如果目标是**先做出可信原型，再决定是否冲更大胆方向**，建议顺序：

   最容易出结果；实现成本低；能直接比较“简单 prefix-aware”与“早期层表示调度”的增量价值。

   学术辨识度最高；如果成立，能挑战当前“KV 越多越好”的共识。

   作为更完整系统论文主线；但实验矩阵更大，适合在前两个结论支持后整合。
