# Stage 08: Hypothesis Gen

Below is a synthesized set of **3 final hypotheses**. They keep the **innovator’s novelty**, satisfy the **pragmatist’s feasibility constraints**, and explicitly absorb the **contrarian’s strongest objections**—especially around **real wall-clock speed, deployment realism, and whether query-centric optimization is even the true bottleneck**.

I do **not** collapse the disagreements: in fact, one of the final hypotheses is deliberately a **diagnostic/negative-result hypothesis**, because the contrarian is right that this is a critical empirical uncertainty, not just a caveat.

# Final Hypothesis 1  
## Error-priority dynamic decoding beats confidence-priority pruning — but only if validated on real latency, not FLOPs

### Hypothesis
In DETR/Mask DINO-style decoders, **allocating refinement compute to “likely-to-be-wrong” queries** (high uncertainty / instability / conflict) will produce a better accuracy-latency tradeoff than conventional **confidence-based query pruning**, because easy/high-confidence queries do not need further refinement.

### Why this survives synthesis
- **Innovator’s strongest idea**: the pruning criterion may be fundamentally wrong; “hard” queries deserve compute more than “strong” queries.
- **Pragmatist’s feasibility**: this can be tested quickly on existing checkpoints with **inference-time modifications only**, on COCO val subsets, no full retraining required.
- **Contrarian concern addressed**: we explicitly require **end-to-end latency**, not just decoder FLOPs, and ideally include **PyTorch + deployable backend** measurement where possible. If dynamic control only reduces FLOPs but not wall-clock, the hypothesis fails.

### Rationale
Most dynamic inference work assumes:
- high-confidence queries are most valuable,
- low-confidence queries can be dropped,
- or all queries should receive equal decoder depth.

But for dense detection/segmentation, the queries that most benefit from extra computation are often the opposite:
- occluded objects,
- boundary-ambiguous instances,
- inter-class confusion,
- geometrically unstable box/mask hypotheses.

So the key scientific question is not merely whether dynamic pruning helps, but whether **future utility is inversely related to current confidence**.

### Minimal feasible mechanism
Using an existing Mask DINO / detrex checkpoint:
1. After each decoder layer, compute an **error-priority score** per query using simple proxies such as:
   - class entropy,
   - box delta magnitude across layers,
   - box IoU instability proxy,
   - mask logit variance.
2. Only the top-k “high-risk” queries continue full refinement.
3. Remaining queries are early-frozen / early-exited with their current outputs.
4. Compare against:
   - confidence-based pruning,
   - fixed top-k query reduction,
   - reduced decoder depth.

### Measurable prediction
On COCO val subsets and then full val:
- At **~50% active query budget**, error-priority pruning should outperform confidence-priority pruning by at least **+1.0 AP** at matched query budget;
- and improve **end-to-end batch=1 latency by at least 15%** over baseline full decoding;
- with variance across 3 random 1k-image subsets below **0.5 AP**.

### Failure condition
Reject if any of the following holds:
- gain over confidence-based pruning is **< 1.0 AP** at matched budget,
- end-to-end latency gain is **< 15%**,
- results are unstable across subsets,
- or gains disappear under a more deployment-realistic backend.

### Unresolved disagreement
- **Innovator view**: the criterion shift itself is the key new mechanism.
- **Contrarian view**: even if the idea is conceptually correct, dynamic control may still fail to convert into real deployment gains.
- This is unresolved and must be treated as an empirical question, not assumed away.

# Core Ideas

## Idea 1: Negative-Evidence Query Rejection for DETR/Mask DINO
- Problem gap: 现有 DETR/Mask DINO 推理优化多关注“保留高置信 query”的 top-k 剪枝，但 unified detection/segmentation 中大量 query 本质上是背景或最终 unmatched；针对“明显无用 query”的低成本拒绝机制研究不足，而且很多方法只报 FLOPs，不验证真实端到端时延。
- Core idea: 在 encoder 输出后或 decoder 第 1 层后，加一个轻量 rejector，预测每个 query 是否“注定无用”。训练时用 Hungarian matching 结果生成伪标签：最终 matched query 为正，其余为负；推理时直接丢弃被判定为负的 query，只让保留下来的 query 进入后续 decoder 和 mask head。为降低误杀，采用双阈值策略：高风险 query 保留、明显负样本才删除。
- Why it is new: 不同于常见的 confidence-based top-k 或固定 query budget，这里优化目标是学习“负证据”而不是“最优 query 排名”；这更适合 DETR 中负 query 远多于正 query 的分布，也更容易做成统一的 detection/instance segmentation 插件。相比简单剪枝，方法直接绑定 matched/unmatched supervision，信号更清晰。
- Why it is feasible now: detrex 和 Mask DINO 已提供稳定代码与训练配方；COCO 上可直接得到 Hungarian matching 监督；实现只需在现有 query 表示上加一个 MLP 分类头，不必重写主干网络。即使只有单卡/中等算力，也可先做 frozen-backbone 或轻量 finetune 版本。
- Minimal experiment: 数据集用 COCO 2017；模型先选 DINO-R50 和 Mask DINO-R50；第一步实现 decoder 第 1 层后的 query rejector，并统计不同保留率下的 box AP、mask AP、batch=1 latency。
- Strong baselines: 固定 query 数基线；confidence-based top-k query pruning；随机 query pruning；不加速的原始 DINO/Mask DINO。
- Expected win: 在 AP 小幅下降（box AP ≤ 0.7、mask AP ≤ 0.8）前提下，decoder latency 明显下降，端到端 batch=1 latency 降低，且 p95 latency 不明显恶化；相同保留 query 数下优于 confidence top-k。
- Main risk: query 剪枝节省的是理论 decoder 计算，但真实瓶颈可能在 pixel decoder、mask head 或 memory traffic，导致端到端加速有限；另外误删 small object 或 occluded object 对应 query 会让 AP_small 掉得比整体 AP 更明显。
- 2-week MVP: 在 detrex/Mask DINO 中实现一个 2-layer MLP rejector，使用最终 matched/unmatched 作为标签，只在 inference 打开剪枝；先做 PyTorch eager 下 COCO val2017 的 AP-latency 曲线，再检查被删 query 的空间分布和 small-object 误伤率。

## Idea 2: Risk-Aware Partial Early Exit for Unified Detection/Segmentation Transformer
- Problem gap: decoder early exit 是一个自然方向，但现有思路通常是图像级“整图早停”，容易牺牲小目标、遮挡目标和边界质量；统一 detection/segmentation 模型里，真正缺的是 query 级、风险感知的部分早退机制。
- Core idea: 不是让整张图在某一层统一停止，而是在每个 decoder 层后，为每个 query 估计“是否已足够稳定”。稳定 query 直接早退并冻结其 box/mask prediction，不稳定 query 继续经过后续层 refinement；风险信号可由相邻层预测的一致性、分类熵、box/mask 变化幅度联合构成。最终只对高风险 query 使用完整 decoder 深度。
- Why it is new: 区别于简单 sample-level early exit，这里是 query-level partial exit，且专门为 unified detection + segmentation 设计，因为 mask query 的收敛速度与 box query 不同。方法强调风险控制而非平均层数减少，更适合 dense prediction 的鲁棒性需求。
- Why it is feasible now: DINO/Mask DINO 本来就是逐层 refinement，天然能提取层间稳定性信号；无需新标注，只要记录各层预测结果即可构造 exit criterion。先做 inference-time heuristic，不需要大规模重新训练，就能快速验证是否有 speed-accuracy trade-off。
- Minimal experiment: 数据集用 COCO 2017，模型选 Mask DINO-R50；先实现基于层间 IoU 变化、分类熵和 mask logit 变化的规则式 partial exit，只在后 3-4 个 decoder 层做 query 级冻结。
- Strong baselines: 原始 Mask DINO；全图统一 early exit；固定减少 decoder 层数；Idea 1 的 query rejection。
- Expected win: 在相近端到端 latency 下，整体 AP/PQ 优于全图早退，尤其 AP_small、crowded/occluded 子集 recall、mask 边界质量下降更少；平均 decoder 实际使用层数下降。
- Main risk: 动态控制流可能在部署后端上不友好，真实加速被 kernel launch 和 gather/scatter 抵消；此外，如果多数 query 都必须走满层，收益会很小。
- 2-week MVP: 不改训练，先做 rule-based partial exit：对每层输出计算稳定性分数，达到阈值就停止该 query 的后续更新；在 COCO val 上测平均活跃 query-layer 数、AP、AP_small 和 batch=1 latency。

## Idea 3: Bottleneck-Aware Inference Optimization Benchmark for detrex/Mask DINO
- Problem gap: 当前 CV 大模型推理优化论文常只报告 FLOPs 或平均 AP，缺少统一、可复现的真实推理成本评测，尤其缺少 batch=1 latency、p95 latency、peak memory、不同后端部署表现，以及“动态方法是否真的比静态方法更快”的系统验证。
- Core idea: 基于 detrex 搭建一个 benchmark suite，统一评测 DINO、Mask DINO 及其优化插件在 PyTorch eager / ONNX / TensorRT 下的真实推理成本。除了常规 AP/PQ/mIoU，还系统报告 decoder、pixel decoder、mask head 的 wall-clock 分解，建立“哪个模块才是端到端瓶颈”的 profiling protocol，并以此筛选值得做的方法位点。
- Why it is new: 不是泛泛 benchmark，而是专门针对 query-based unified detection/segmentation Transformer 的 inference optimization protocol；它能直接回答“query pruning/early exit 是否只是 FLOPs illusion”。相较单一方法论文，这个工作可成为后续动态优化研究的公共基线和过滤器。
- Why it is feasible now: detrex 已经统一了多个 DETR 变体的训练和模型接口；COCO evaluation 成熟；PyTorch profiler、ONNXRuntime、TensorRT 都可直接接入。即使 TensorRT 支持不完整，也可先完成 PyTorch + ONNX 的第一版。
- Minimal experiment: 数据集用 COCO val2017；模型用 DINO-R50、Mask DINO-R50、Mask DINO-Swin-T；第一步固定输入分辨率与 batch=1，测模块级 latency breakdown，并输出 AP-latency-memory Pareto 表。
- Strong baselines: 原始模型官方实现；固定减层/减 query 的静态瘦身；已有动态 query pruning 或 early exit 实现；不同后端默认导出配置。
- Expected win: 不以“指标提升”定义 win，而是形成一套可复现结论：哪些模块占主要 wall-clock，哪些优化在真实后端上有效，哪些只是 FLOPs 下降但几乎不加速。理想结果是能发现 pixel decoder/mask head 与 decoder 的真实占比，并指导后续方法设计。
- Main risk: benchmark 型工作方法创新度较弱，若没有顺带提出一个小而有效的优化插件，论文新颖性可能不够；此外 TensorRT/ONNX 导出会消耗不少工程时间。
- 2-week MVP: 完成 DINO-R50 与 Mask DINO-R50 在 COCO val2017 上的统一 profiling 脚本，输出 batch=1 latency、peak memory、模块级占比，并复现一个简单静态基线（如减少 decoder 层）作为 sanity check。

## Recommended First Try
**Idea 1: Negative-Evidence Query Rejection for DETR/Mask DINO**

这个方向最适合先做，因为它兼顾了新颖性、实现复杂度和论文可讲性：只需在现有 DINO/Mask DINO 上增加一个轻量模块，就能直接验证真实 latency-AP trade-off。相比纯 benchmark，它更容易形成方法贡献；相比 partial early exit，它控制流更简单、工程风险更低。

## Hypothesis 1 — Negative-evidence query rejection is a better low-cost pruning signal than confidence-based top-k, but only if it improves real latency on static-friendly backends

### Rationale
This takes the innovator’s most novel idea: **predict which queries are doomed to be useless**, rather than trying to identify the best ones early. It is more feasible than region-level attention replacement and aligns with the pragmatist’s recommendation to work directly in **Mask DINO / DINO / detrex** with a small add-on module.

It also addresses the contrarian critique by making the claim explicitly about:
- **end-to-end latency**, not just FLOPs,
- **p95 latency/jitter**, not just mean latency,
- and comparison against a **hardware-friendly static baseline**, not only dynamic top-k pruning.

Why this is strong:
- Background/unmatched queries are abundant in DETR-like models.
- Learning “definitely useless” may be easier and more stable than learning “most useful.”
- A small rejector can be trained without full model retraining.

### Measurable prediction
On **DINO-R50 or Mask DINO-R50**, using a frozen backbone/decoder plus a lightweight rejector trained from final matched/unmatched pseudo-labels:

- Removing **30–40% of initial queries before or very early in decoding** yields:
  - **decoder latency reduction ≥ 20%**
  - **end-to-end latency reduction ≥ 10%**
  - **box AP drop ≤ 0.7** and **mask AP drop ≤ 0.8**
- Compared with confidence-based top-k pruning at equal retained query budget:
  - **lower p95/mean latency ratio**
  - **better AP_small and occluded-subset recall retention**

To satisfy the contrarian concern, this must hold on at least **PyTorch eager and one deployment backend** (ONNX or TensorRT), not only in framework-level profiling.

### Failure condition
Reject the hypothesis if any of the following hold:

- End-to-end latency gain is **< 8%**
- AP drop is **> 1.2** for detection or **> 1.5** for instance segmentation
- p95 latency worsens materially relative to static or confidence-pruning baselines
- Gains appear only in FLOPs/decoder profiling but **do not survive real backend execution**
- AP_small / long-tail / occlusion metrics degrade disproportionately even when overall AP looks stable

### Unresolved disagreement
- **Innovator/pragmatist view:** negative-evidence pruning is a practical and novel dynamic inference method.
- **Contrarian view:** any per-sample dynamic pruning may fail to produce real deployment gains because of indexing/control-flow overhead.
- The disagreement is empirical and should be tested directly via backend-aware benchmarking.

## Hypothesis 2 — Decoder early exit is useful only when reformulated as risk-aware partial exit, not naive sample-level stopping

### Rationale
This synthesizes the pragmatist’s strongest feasible direction—**decoder early exit**—with the contrarian’s most important warning: naive early exit may preserve mean AP while harming **small objects, occluded instances, rare classes, calibration, and boundaries**.

So the final hypothesis is not generic early exit. It is:

> **Partial, risk-aware early exit**—where easy/high-certainty queries stop updating while uncertain/high-risk queries continue—will outperform global image-level early exit at the same latency budget.

This keeps the idea deployable within Mask DINO/DINO and avoids the innovator’s highest-risk structural changes.

### Measurable prediction
Using decoder-layer prediction stability and uncertainty signals:

- A **partial exit** policy reduces average decoder depth usage by **25–35%**
- Gives **end-to-end latency reduction ≥ 8–15%**
- Keeps overall **box AP / mask AP drop ≤ 0.8**
- At matched latency, compared with **global early exit**:
  - better **AP_small**
  - better **occluded/crowded-scene recall**
  - lower **ECE / calibration error**
  - less degradation in boundary-sensitive segmentation metrics

This can begin as an inference-only policy, then optionally add lightweight finetuning with layer-consistency loss.

### Failure condition
Reject the hypothesis if:

- Most samples still need full-depth decoding, giving **< 5–8% end-to-end gain**
- Partial exit does not beat global early exit on risk-sensitive metrics at equal latency
- Calibration or AP_small collapses despite minor overall AP change
- Dynamic branching overhead erases practical speed benefits on deployment backends

- **Pragmatist:** early exit is among the most realistic ideas to test quickly.
- **Contrarian:** average-speed gains may hide robustness failures and backend inefficiency.
