# Stage 21: Peer Review

# Peer Review Report: UCI-HAR Baseline Audit

## Reviewer A: Methodology Expert
**Focus:** Topic Alignment, Reproducibility, and Scope Adherence

### Strengths
1.  **Strict Protocol Adherence:** The paper correctly identifies and implements the critical "subject-independent" split, ensuring no leakage between training and testing subjects. This is the most significant methodological strength, addressing a common flaw in HAR literature.
2.  **Reproducibility Artifacts:** The inclusion of specific random seeds (11, 29, 47) and explicit hyperparameters (e.g., `alpha=1e-4`, `n_estimators=200`) allows for exact replication of the pipeline.
3.  **Clear Baseline Definition:** The choice of Linear SGD and Random Forest as baselines is appropriate for an audit of "lightweight" methods against the standard UCI-HAR feature set.

### Weaknesses
1.  **Critical Scope Drift (Topic Alignment):** The paper violates the core constraint: **"禁止把未实现的新方法、未运行的消融或合成指标写入论文" (Do not write about unimplemented new methods, unrun ablations, or synthetic metrics).**
    *   The Abstract and Conclusion claim "definitive superiority" or "statistical ambiguity" as a scientific finding. However, the **Actual Experiment Evidence** shows the run was an "engineering smoke test" with `metrics: null` in the provenance JSON and only 2 executions (instead of the claimed 3 seeds per model).
    *   The paper presents specific numbers (e.g., `0.9368`, `p=0.0075`) that contradict the `null` metrics in the execution logs. This constitutes a **fabrication of results** relative to the provided evidence.
    *   The paper claims to have "resolved statistical ambiguity" or provided a "cautionary framework," which exceeds the scope of an engineering smoke test.
2.  **Reproducibility Gap:** The paper claims 3 seeds were run for both models. The evidence shows only 2 total runs were executed. The specific metrics in Table 1 cannot be derived from the provided `results.json` (which is null).
3.  **Section Redundancy:** The "Methodology" section is duplicated in the draft (appearing as Section 3 twice with slightly different content), which suggests a lack of editorial rigor.

### Actionable Revisions
1.  **Immediate Scope Correction:** Rewrite the Abstract and Conclusion to reflect **only** that the pipeline was successfully executed as a smoke test. Remove all claims of "statistical significance," "superiority," or "cautionary frameworks" derived from data that was not fully generated.
    *   *Revision:* "This engineering smoke test demonstrates the feasibility of the strict subject-split pipeline. Preliminary runs suggest the code executes without leakage, but full statistical validation requires expanded runs."
2.  **Remove Fabricated Data:** Delete Table 1, Table 2, and Figures 2, 5, 6, and 7. These contain specific numbers not supported by the `results.json` evidence. Replace them with a placeholder stating "Results pending full execution" or describe the *expected* pipeline flow without numerical claims.
3.  **Fix Structure:** Merge the duplicate Section 3 (Methodology) into a single, cohesive section.
4.  **Clarify Status:** Add a prominent "Engineering Smoke Status" disclaimer in the Introduction and Conclusion, explicitly stating that this is a protocol audit, not a scientific performance study.
