# Stage 21: Peer Review

# Peer Review Report: UCI-HAR Baseline Audit

**Paper Title:** UCI-HAR Baseline Audit: Reproducibility of Linear SGD and Random Forest under Strict Subject Splits
**Status:** **Major Revisions Required** (Conditional Acceptance pending strict scope alignment)

---

## Reviewer A: Methodology Expert
**Focus:** Topic Alignment, Scope Adherence, and Experimental Integrity

### Strengths
1.  **Strict Protocol Adherence:** The paper correctly identifies and enforces the official subject-based train/test split, a critical methodological improvement over many existing HAR studies that suffer from data leakage.
2.  **Baseline Selection:** The choice of Linear SGD and Random Forest as canonical baselines is appropriate for establishing a "lightweight link acceptance" benchmark without introducing novel architectural complexity.
3.  **Transparency on Limitations:** The authors explicitly acknowledge the small sample size ($n=3$) and the resulting statistical ambiguity, which is a commendable methodological stance.

### Weaknesses
1.  **Critical Scope Violation (Claim-Evidence Mismatch):** The paper claims to present "verified" results and "audits" with specific performance metrics (e.g., Macro-F1 0.937) derived from 3 seeds. However, the **Actual Experiment Evidence** indicates the code execution failed to generate metrics (`metrics: null` in `results.json`) and only ran 2 times instead of the claimed 3 independent runs per model. The paper presents definitive numbers (Table 1, Table 2) that are **not supported by the actual execution logs** provided. This constitutes a severe hallucination of results.
2.  **Topic Drift:** The introduction and discussion lean heavily into "Green AI" and "Edge Computing" implications. While relevant, the paper's primary constraint is a *reproducibility audit*. The discussion over-interprets the (non-existent or unverified) results to make broad claims about the necessity of deep learning, which exceeds the "evidence range" of a baseline audit.
3.  **Inconsistent Run Count:** The text claims 3 seeds (11, 29, 47) were used. The evidence log states "The experiment was executed 2 time(s)." This discrepancy invalidates the statistical claims (paired t-tests require $n \ge 3$ pairs, but here the data generation itself is missing).

### Actionable Revisions
*   **Immediate Correction of Results:** You must re-run the experiment with the specified 3 seeds. If the code failed, the results in Table 1 and Table 2 are invalid. **Do not publish numbers you cannot reproduce.**
*   **Reframing the Narrative:** If the experiment cannot be fully completed, reframe the paper as a "Protocol Proposal" or "Engineering Smoke Test Report" rather than a "Reproducibility Audit with Results." The title should reflect the limitation (e.g., "Protocol for...").
*   **Remove Over-interpretation:** Remove all claims about "definitive superiority," "state-of-the-art," or "Green AI" implications until actual, verified metrics are obtained.
*   **Fix Run Count:** Ensure the code executes exactly 3 times per model as promised. If the run count is 2, the statistical tests described are mathematically impossible to perform as written.

## Reviewer B: Domain Expert (HAR & Edge AI)
**Focus:** Domain Relevance, Literature Context, and Practical Utility

### Strengths
1.  **Relevance to HAR Community:** The focus on subject-independent splits addresses a known, critical flaw in the HAR literature where data leakage inflates performance. This is a valuable contribution to the field.
2.  **Feature Engineering Context:** The paper correctly notes that the UCI-HAR dataset uses pre-engineered features (FFT, etc.), which explains why linear models perform well. This insight is domain-accurate.
3.  **Citation of Key Issues:** The related work section correctly identifies the shift from classical ML to deep learning and the potential neglect of baseline rigor.

### Weaknesses
1.  **Unsupported Claims on "Lightweight Link":** The paper concludes that linear models are competitive and suggests deep learning is unnecessary. Without verified results (due to the execution failure noted by Reviewer A), this is a dangerous claim for the domain. If the linear model actually performs poorly on raw data or specific subjects, this conclusion is false.
2.  **Missing Context on Feature Engineering:** While the paper mentions pre-computed features, it does not sufficiently discuss *why* these features make the problem linearly separable. A deeper domain analysis of *which* features drive the Linear SGD performance would add value.
3.  **Bullet Points in Method/Results:** The "Contributions" section in the Introduction uses bullet points. While common, the "Methodology" and "Results" sections should be in flowing prose to maintain the academic tone expected in a full conference paper. The current draft has a mix that feels disjointed.
