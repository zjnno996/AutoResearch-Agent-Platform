# 发布与敏感信息处理

公开仓库保留前后端源代码、配置模板、测试、文档与附带许可证的技能资源。

以下内容保留在本机，不随 Git 提交：

- 仓库外的 `provider.env`、API Key、认证密钥及环境文件；`.env.example` 仅含公开示例。
- `backend/runs/` 中的用户、项目、队列、固定运行快照和模型交互数据。
- `backend/review_history/`、`backend/review_cache/` 和 `docs/kb/` 中的评审、原文缓存及研究笔记。
- 本地数据集、检查点、模型输出、日志、虚拟环境、浏览器测试产物与内部工作记录。

公开配置不固定某台服务器的内网地址或解释器路径。服务地址通过 `EMNETS_API_BASE` / `OPENAI_BASE_URL` 指定；未配置时仅使用本机兼容服务默认地址。凭据通过 `RESEARCHCLAW_API_KEY` 等后端环境变量读取。已有部署的私有环境不会因更新代码而被覆盖。

提交前检查实际暂存内容，而不仅是 `.gitignore`。对于早期已被跟踪的运行文件，使用 `git rm --cached` 停止跟踪，保留磁盘上的本地数据。只发布目标分支需要的提交，不推送本机全部远程引用或工作区归档。

使用凭据扫描器检查候选目录及目标分支历史，并另外核对真实部署凭据、内网地址、账号数据库和私钥文件名。文献引用键、密码验证测试和第三方文档示例可能造成误报；逐项核实其上下文，不能关闭整类凭据检测来隐藏真实问题。提交作者可使用 GitHub 的隐私邮箱。

技能原始资源及其许可证保持完整；发布时不把公开作者署名、来源链接或许可证文本误当作需要删除的敏感词。供应商专属地址、私有实验文件和个人工作记录不属于开源资源来源说明。
